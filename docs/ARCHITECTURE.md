# Discord in CLI 아키텍처 📐

> 프로그램이 **안에서 어떻게 돌아가는지** 알고 싶다면 이 문서를 보세요!
> **코드를 안 읽어도** 구조를 이해할 수 있게 쉽게 설명했어요.
> (Rust로 다시 쓰여진 버전 기준이에요.)

---

## 1. 전체 구조 한눈에 보기 🗺️

이 프로그램은 **Rust 모듈 9개**가 팀을 이뤄서 돌아가요.
`main.rs`가 대장이고, 나머지 모듈들이 각자 일을 맡아요.

```
discord_in_cli/
├── Cargo.toml              ← 📦 프로젝트 설정 & 외부 라이브러리
└── src/
    ├── main.rs             ← 🧠 대장 (프로그램 시작점)
    ├── config.rs           ← ⚙️ 설정 담당 (settings.json)
    ├── state.rs            ← 🗃️ 공용 상태 관리
    ├── handler.rs          ← 📨 디스코드 이벤트 수신
    ├── console.rs          ← ⌨️ 터미널 입력 처리
    ├── fmt.rs              ← 🎨 출력 담당 (색깔, 멘션, 프린트)
    ├── embed.rs            ← 🃏 임베드/컴포넌트 렌더링
    ├── image.rs            ← 🖼️ 이미지 렌더링
    └── log.rs              ← 📝 파일 기록 담당
```

> 💡 `main.rs`가 시작되면 `handler.rs`(디스코드 이벤트)와 `console.rs`(터미널 입력)가
> **동시에** 돌기 시작해요. 둘 다 `state.rs`에 있는 공용 상태를 보고 일해요.

## 2. 누가 누구를 부르나요? (의존 관계) 🔗

```
                ┌─────────────────────────────┐
                │          main.rs            │
                │           (대장 🧠)          │
                └──────────┬──────┬───────────┘
                           │      │
              ClientBuilder│      │ settings.json
                           ▼      ▼
                ┌─────────────────────────────┐
                │         state.rs            │
                │     (공용 상태 🗃️)          │
                └──────┬──────────┬───────────┘
                       │          │
        ┌──────────────▼──┐   ┌───▼──────────────┐
        │   handler.rs    │   │   console.rs     │
        │  📨 이벤트 수신  │   │   ⌨️ 입력 처리    │
        └──────┬──────────┘   └──────┬───────────┘
               │                     │
               ▼                     ▼
        ┌────────────────────────────────────────┐
        │ fmt.rs 🎨 · embed.rs 🃏 · image.rs 🖼️ · log.rs 📝 │
        │ (출력과 기록은 이 4명이 다 해요)          │
        └────────────────────────────────────────┘
```

| 모듈 | 주로 쓰는 것 | 한 줄 설명 |
|------|-------------|-----------|
| `main.rs` | `config`, `state`, `handler` | 설정 읽고 봇 시작 |
| `config.rs` | `serde` | `settings.json` 파싱 |
| `state.rs` | `serenity` 모델 | 선택 채널·메시지 버퍼·보기 토글 공유 |
| `handler.rs` | `serenity` 이벤트 | 메시지/수정/삭제 이벤트 처리 |
| `console.rs` | `serenity` HTTP | `/명령어` 실행 (전송·편집·다운로드 등) |
| `fmt.rs` | ANSI escape | 색깔 출력, 멘션 정리, 메시지 그리기 |
| `embed.rs` | — | 임베드/버튼을 터미널 박스로 |
| `image.rs` | `image`, `reqwest` | 이미지를 글자 블록으로 |
| `log.rs` | `serde_json` | 텍스트/JSON으로 기록 |

## 3. 메시지가 왔을 때 일어나는 일 📨

누군가 디스코드에서 채팅을 치면, 이 순서대로 일이 벌어져요:

```
 디스코드 서버에서 메시지 발생! 💬
          │
          ▼
 ① handler.rs의 message()가 받아요
          │
          ▼
 ② "내가 보고 있는 채널의 메시지야?" 확인
          │
     ┌────┴────── 아니야 ──→ 무시! (끝)
     │
     ▼ 맞아!
 ③ state.rs 버퍼에 추가 (최근 N개만 보관)
          │
          ▼
 ④ 내가 보낸 메시지면? → 화면엔 안 보여주고 끝
          │
          ▼ 아니야
 ⑤ fmt.rs로 출력 (멘션됐으면 주황색 배경!)
          │
          ▼
 ⑥ log.rs로 파일 기록
          │
          ▼
 ⑦ 임베드/이미지 있으면 embed.rs / image.rs 호출
          │
          ▼
 ⑧ 끝! 다음 메시지 기다리기 🔁
```

> ⚠️ 수정(`message_update`)이나 삭제(`message_delete`)도 거의 같은 순서예요.
> 다만 화면에 `Modified` 나 `Deleted` 라고 다르게 표시해줘요.
> 수정 전 내용을 보여주기 위해 serenity 캐시(메시지 보관)를 켜두고,
> `state.rs`의 메시지 버퍼와 함께 사용해요.

## 4. main.rs — 대장은 뭘 하나요? 🧠

1. `settings.json`을 읽어요 (없으면 오류 메시지 후 종료).
2. `State`를 만들어요 — 모든 모듈이 공유할 상태.
3. stdin을 읽는 스레드를 띄워요 (터미널 입력 → 채널로 전달).
4. serenity `ClientBuilder`로 봇을 만들어요.
   - Gateway Intents: `GUILDS`, `GUILD_MEMBERS`, `GUILD_MESSAGES`, `DIRECT_MESSAGES`, `MESSAGE_CONTENT`
   - 캐시에 메시지를 보관하도록 설정 (수정/삭제 표시용)
5. `client.start()` — 디스코드에 연결돼요.

## 5. handler.rs — 이벤트 수신 📨

| 함수 | 언제 호출? | 하는 일 |
|------|-----------|---------|
| `ready()` | 봇이 켜졌을 때 (딱 1번) | "Logged in as" 출력, 채널 목록 표시, 콘솔 루프 시작 |
| `message()` | 새 메시지가 올 때마다 | 버퍼에 추가 + 화면에 표시 + 저장 |
| `message_update()` | 메시지가 수정됐을 때 | "수정전 → 수정후" 보여주기 + 저장 |
| `message_delete()` | 메시지가 삭제됐을 때 | "삭제됨" 표시 + 저장 |

## 6. console.rs — 터미널 입력 처리 ⌨️

`ready()`가 끝나면 콘솔 루프가 시작돼요. 입력 한 줄씩 받아서:

```
  "/" 로 시작해? ──── 아니 ──→ 채팅 메시지로 전송!
      │
      ▼ 응, 명령어야
  어떤 명령어?
  ├─ /select       → 채널 전환 (지난 메시지도 불러옴)
  ├─ /exit         → 채널 선택 해제
  ├─ /embed        → 임베드 보기 토글
  ├─ /img          → 이미지 보기 토글
  ├─ /status       → 현재 상태 확인
  ├─ /stop         → 봇 종료
  ├─ /setrpc       → 봇 활동 변경
  ├─ /refresh      → 최근 메시지 다시 불러오기
  ├─ /messages     → 최근 메시지 목록 확인
  ├─ /edit         → 내가 보낸 메시지 수정
  ├─ /editmsg      → 메시지 ID로 수정
  ├─ /reply        → 특정 메시지에 답글 전송
  ├─ /uploadfile   → 파일 업로드
  ├─ /downloadfile → 첨부파일 다운로드
  └─ 그 외         → "모르는 명령어" 에러
```

## 7. fmt.rs — 출력 담당 🎨

- **ANSI truecolor**로 색을 입혀요 (외부 라이브러리 없이 직접):
  - 봇 닉네임: 보라 `#B4009E`
  - 멘션 알림: 주황 `#EA9800` on 진한 배경 `#2B251C`
- `resolve_markup()` — `<@123>` 같은 멘션을 `@이름`으로, 커스텀 이모지 `<:name:id>`를 `:name:`으로 바꿔요 (파이썬 버전의 `clean_content` 역할).
- `convert_names_to_mentions()` — 보낼 때 `@닉네임`을 진짜 `<@ID>` 멘션으로 변환 (서버 멤버 목록에서 이름 검색).
- `print_discord_msg()` — 메시지를 한 줄로 출력하고, 임베드/이미지가 있으면 각 모듈 호출.

## 8. embed.rs — 화가 🃏

임베드를 rich 스타일 박스(`╭─╮`)로 그려요:

| 임베드 요소 | 터미널에서 이렇게 보여요 |
|------------|----------------------|
| 👤 작성자(author) | 볼드 시안 색으로 표시 |
| 📌 제목(title) | 볼드 흰색으로 표시 |
| 📝 설명(description) | 일반 텍스트 |
| 🔹 필드(fields) | 인라인 필드는 3열로 가지런히 정렬 |
| 🖼️ 이미지/썸네일/비디오 | URL 링크로 표시 |
| 📅 푸터/타임스탬프 | 이탤릭 흐린 글씨 |

UI 컴포넌트: 버튼 `[ 이름 ]` (시안), 셀렉트 메뉴 `▼ ... (Selection Menu)` (마젠타).

## 9. image.rs — 사진사 🖼️

이미지를 다운받아 **유니코드 반블록 문자(`▀`)로** 터미널에 그려요.
예전 파이썬 버전의 `climage` 라이브러리와 같은 방식이에요:

```
① 이미지 첨부파일 발견
② reqwest로 다운로드
③ image 크레이트로 디코딩 → 너비 50으로 리사이즈
④ 각 픽셀 쌍(위/아래)을 '▀' 문자 + ANSI 색으로 변환
⑤ 박스로 감싸서 출력
```

## 10. log.rs — 서기관 📝

`SAVE_AS_JSON` 설정에 따라 두 가지 형식으로 저장해요:

**📄 텍스트 모드** — 사람이 읽기 편한 형식:
```
[2026-07-01 12:34:56] [서버 / 채널] 닉네임(ID): 안녕하세요~
[2026-07-01 12:35:00] [서버 / 채널] 닉네임(ID) 수정됨: 안녕 → 안녕하세요
[2026-07-01 12:35:30] [서버 / 채널] 닉네임(ID) Deleted: 안녕하세요
```

**📋 JSON 모드** — 프로그램이 읽기 편한 형식 (JSON 라인):
```json
{"type":"message","timestamp":"2026-07-01T12:34:56Z","server":{"id":123,"name":"서버"},"channel":{"id":456,"name":"채널"},"author":{"id":789,"name":"닉네임","is_bot":false},"content":"안녕하세요~","attachments":[]}
```

## 11. 사용된 외부 라이브러리 📦

| 크레이트 | 어디서 쓰나 | 하는 일 |
|-----------|-----------|---------|
| `serenity` | 전체 | 디스코드 API 연결 (게이트웨이 + REST + 캐시) |
| `tokio` | 전체 | 비동기 런타임 |
| `serde` / `serde_json` | `config.rs`, `log.rs` | 설정 파싱, JSON 기록 |
| `chrono` | `fmt.rs`, `log.rs` | 시간 표시 |
| `reqwest` | `image.rs`, `console.rs` | 이미지/첨부파일 다운로드 |
| `image` | `image.rs` | 이미지 디코딩/리사이즈 |
| `regex` | `fmt.rs` | 멘션·이모지 정규식 처리 |
